# Grok bridge verification

## Routines: мост проверяет мост

`scripts/soak.py` доказывает, что четыре роли ещё работают. `scripts/routines.py` доказывает
обещания вокруг них: что отказ гнёт работу, а не убивает; что секрет не доезжает до receipt;
что воркер не «прибрался» в файле, о котором не просили; что один опрос остаётся дешёвым,
сколько бы job ни длился. Одна рутина — одно обещание — один вердикт, читаемый из receipt.
Слова агента о себе не считаются нигде.

| | |
|---|---|
| `py -3 scripts/routines.py --list` | каталог: id, измерение, драйвер, что доказывает |
| `py -3 scripts/routines.py --dimension audit` | восемь аудитов: gate, экономия, приёмка, roots, протокол, жизненный цикл, документация, тесты |
| `py -3 scripts/routines.py --harness-only` | секунды, без воркера — годится в каждый прогон |
| `py -3 scripts/routines.py --dimension security` | одно измерение |
| `py -3 scripts/routines.py` | всё целиком, включая аудиты — десятки минут |

Драйвер `harness` гоняет мост из питона там, где ответ обязан быть одинаковым. Драйвер `grok`
платит за живого воркера, потому что интересные поломки — те, которые детерминированный
скрипт не догадался бы попробовать. Рутины `audit.*` — это Grok, читающий сам мост по
брифу из `routines.py`: он отдаёт отчёт файлом в свою lane, и каждая ссылка `read: file:line`
из этого отчёта **перепроверяется** по дереву — файл существует, строка в диапазоне,
процитированный текст рядом. Ссылка, которая не сходится, роняет прогон. Иначе воркер мог бы
приложить один настоящий прогон pytest и выдумать всё остальное: `finalize_receipt` смотрит
только на объявленную команду и про JSON рядом не знает ничего.

Результат — `Service/Audits/routines-<stamp>.json` (в git не едет). В каждой строке лежит
срез receipt, который решил вердикт, и `repro` — та единственная команда, что вернёт находку
на стенд. Это и есть форма, в которой хост забирает работу: **Grok находит, Claude
воспроизводит, чинит, дописывает тест**. Отчёт воркера доказательством не является.

Порядок правки рутины тот же, что и всего остального: сначала убедиться, что негодный зонд —
не сама рутина. За один заход этой работы трижды красным оказывалась проверка, а не код:
`prepare_worktree` без `ensure_lane_dir_ignored` перед ним, `require_clean_base` не как в
рантайме, и `PROJECT_PRESET_OFF` в `reason`, а не в `error`.

## Цикл доводки

Оператору не нужно каждый раз объяснять, что «ещё не идеал, дорабатывай». Триггер — **«продолжай цикл»**. Дальше агент идёт сам, без вопросов, пока не выполнено условие готовности.

**Готово** — это не ощущение, а список, который можно опровергнуть:

1. `py -3 scripts/soak.py` — все строки зелёные **два прогона подряд**. Один зелёный прогон не считается: половина найденного здесь плавает.
2. `py -3 -m pytest tests -q` зелёный, и после каждой правки он **вырос**. Не вырос — значит правка не покрыта, и тест надо дописать.
3. Ни одного `ACP_STOP_cancelled` из-за отказа гейта. Оговорка, купленная захватом: мост уже отвечает `reject_once`, а CLI после отказа на **запись** всё равно шлёт `session/cancel` (`evidence/live-acp/session-permission-cancel.jsonl`). Гейтом это не чинится — чинится тем, что роль вообще не тянется к запрещённому: `build_prompt` говорит read-only роли, что писать нельзя и что отказ убьёт ход. Отдельно: исчерпание ходов тоже даёт `ACP_STOP_cancelled` и это штатный успех — verifier и коммит всё равно есть. Судить по сути (прогнан ли verifier, лёг ли коммит), а не по строке.
4. Ни одного `ACP_OUTPUT_LIMIT`: длинный честный отчёт скептика должен доходить целиком. Бюджет считает **текст агента**, а не кадры: медианный кадр `agent_message_chunk` — 456 байт на 2–8 байт текста, а `tool_call_update` пересылает весь накопленный вывод команды заново, поэтому один прогон pytest выглядел как мегабайты «вывода агента». Растущий буфер под одним `toolCallId` теперь оплачивается только приростом. И само превышение больше не убивает ход: это отмена, как исчерпание ходов, — правки на диске остаются, verifier их судит, в receipt стоит `output_truncated`.
5. Один опрос ≤ 16 KiB при любой длине job'а — и это про **собранный ответ**, а не про внутреннюю запись. MCP-конверт кладёт результат **дважды**: `structuredContent` и тот же JSON текстом, для совместимости со старыми клиентами, которые читают только `content.text`. Пока бюджет мерили по записи, обещанные 16 KiB уезжали в 32 345 B на проводе. Теперь `fit_poll_budget` ужимает так, чтобы в кап влез весь `tools/call` result, а `content.text` сериализуется компактно (`indent=2` стоил 72% на `tools/list`). Дубликат остаётся — убрать его значит сломать этих клиентов. Мерить **байтами провода**: сервер пишет `ensure_ascii=False` в UTF-8, и подсчёт экранированных символов раздувает кириллицу втрое (`economy.wire_size`, `economy.tool_result_wire_size`).
6. Скептик доказал **запуском**, а не чтением: в его receipt есть прогон, который он сделал сам.
7. Исполнитель дал `changed_files`, тест от `bridge-verifier` и коммит в `grok/*`.

Пока хоть одна строка красная — цикл не закончен. Порядок один и тот же: **воспроизвести → починить → дописать тест, который поймал бы → перепрогнать всё целиком → повторить**. Разрешения на следующую итерацию не спрашивать.

**Бюджеты асимметричны, и это главное.** У воркера лимитов нет: `max_turns` высокий, `reasoning_effort` xhigh, job'ов столько, сколько нужно, чтобы что-нибудь погнулось. Экономить надо **контекст хоста**, а не работу Grok'а. Занижать бюджет воркера «ради экономии» — это путать две разные вещи.

Правила, которые в этом цикле уже стоили денег:

- Находка без воспроизведения — не находка. Прогнать и показать вывод.
- Зелёный набор ничего не доказывает про новую правку: он проверяет то, о чём кто-то подумал.
- **Правка ответа на проводе обязана иметь тест на обе ветки — с compact и без.** Живой прогон доказывает один вход, тест держит контракт. `_poll_ok` уехал в 0.27.0 без единого теста: правку проверили прогоном на типизированном пути, а навигатор включает compact сам, и там `ok` оставался `true` для **любого** статуса — blocked, failed, cancelled, no_changes. Дешёвый цикл навигатора — не частный случай, а основной путь.
- **Тест, который ходит через гейт, проверяет машину, а не код.** Тест на карточку навигатора звал `session_begin` и брал первую карточку — а какая она, решает гейт: без установленной CLI и логина первая карточка другая. Зелено там, где писали; красно на обеих строках CI. Звать сборщик пакета напрямую.
- Свой код проверять так же, как чужой. Три бага подряд были в коде, написанном за час до этого.
- Отчёт агента — не доказательство. Доказательство — receipt и собственный прогон.

## Финализация: что происходит само, без вопросов

Оператор не обязан объяснять, чем заканчивается задача. Заканчивается она одинаково, и разрешения на эти шаги не спрашивают.

**Кто что делает.** Grok — воркер: пишет код и тесты в своей lane `grok/*`, дальше не идёт. Хост (Claude) — оркестратор и приёмщик: проверяет своим прогоном, чинит, коммитит в `main`, выпускает. Отчёт агента не доказательство; доказательство — receipt и собственный прогон.

**Порядок в конце каждого среза:**

1. `py -3 -m pytest tests -q` зелёный и **вырос**. Локальный зелёный — это ещё
   не CI: здесь Python 3.14, а матрица гоняет 3.10 и 3.13 на Windows и Linux,
   и «сколько стека осталось» — свойство рантайма, а не кода. Два релиза
   подряд ушли красными ровно поэтому: `payload_bytes` на глубоком кадре
   падал на 3.10/3.13 и проходил на 3.14. Перед тегом прогнать набор ещё и на
   **младшем** интерпретаторе, а после пуша **посмотреть** CI, а не считать
   его зелёным по умолчанию: `gh run list --limit 3`.

   ```
   /absolute/path/to/lowest-supported-python -m pytest tests -q
   ```

   Тест, который зависит от платформы, помечать `skipif` сразу: `mklink /J`
   есть только на Windows, и два теста уронили Linux-строки матрицы.
2. `py -3 scripts/soak.py` зелёный два раза подряд — если трогали то, что job видит на проводе.
3. Запись в `CHANGELOG.md`: наблюдаемое снаружи — в текущую версию, ненаблюдаемое — под `## Unreleased`.
4. Видно снаружи → bump всех четырёх мест, тег `vX.Y.Z`, `gh release create`. Не видно → копится под `Unreleased`, релиза нет.
5. Коммит и `git push origin main`.
6. Клон, из которого запущен MCP, обновить: `git pull` + `pip install -e .`.
7. Одна строка оператору: версия, что чинилось, нужен ли перезапуск.

**Перезапуск хоста нужен всегда, когда менялся код пакета** — сервер держит модули в памяти. Не менялся (доки, тесты, CI) — не нужен.

**Чего не делать никогда:** мержить `grok/*` за оператора, пушить force, тегировать красное дерево, спрашивать «выпускать ли», спрашивать «продолжать ли цикл».

**Когда останавливаться и спросить:** правка меняет модель доверия (что гейт пускает, куда мост пишет, чей секрет читает), либо ломает уже настроенных пользователей сверх того, что закрывается пометкой **Breaking:**.

## Changelog

Запись в `CHANGELOG.md` — часть изменения, а не отдельная задача «потом». Правило простое: **всё, что видно снаружи, попадает в changelog в том же коммите или PR**. Снаружи видно схемы инструментов, ответы на проводе, дефолты, переменные окружения, отказы, шаги установки. Внутренний рефакторинг, ничего не меняющий наблюдаемо, записи не требует.

Пишем **зачем**, а не что: что именно изменилось, покажет diff, а читателю нужно решить, обновляться ли ему. Поэтому запись называет симптом. «`initialize` теперь читает запрошенную версию» полезнее, чем «правка в `server.py`».

- Незарелиженное копится под `## Unreleased`; при выпуске этот заголовок **становится** версией, новая секция не заводится.
- Ломающее помечается **Breaking:** и говорит, что увидит уже настроенный пользователь. Переехавший дефолт — ломающий, даже если ошибку никто не получит.
- Semver считается по MCP-поверхности: изменённая схема инструмента, изменённый ответ на проводе или переехавший дефолт — минимум minor. Исправление, не трогающее поверхность, — patch.
- Заголовок релиза — название, а не номер: `## X.Y.Z — <что это за релиз>`.

Формат и место версии описаны в шапке самого `CHANGELOG.md`. Не дублировать их здесь — разойдутся.

## Релиз

Версия живёт в четырёх местах и они обязаны совпадать: `pyproject.toml`, `SERVER_VERSION` в `grok_delegate/guard.py` (источник истины — пакет читает оттуда, `__init__.py` реэкспортирует, тест запрещает остальным модулям писать литерал), бейдж в `README.md`, строка в `docs/CODEX-MCP-SETUP.md`.

Порядок: зелёный набор → bump всех четырёх → `## Unreleased` превращается в `## X.Y.Z — <название>` → коммит → `git tag -a vX.Y.Z` → `git push origin main` → `git push origin vX.Y.Z` → `gh release create vX.Y.Z -F <notes>`.

Тег и релиз идут вместе. Тег без релиза — это версия, которую никто не увидит: страница GitHub показывает релизы, а не теги, и репозиторий с одним релизом читается как вчера появившийся. Заметки к релизу берутся из секции changelog этой версии; переписывать их заново не надо, но футер «Unofficial community project» в них нужен.

Не тегировать красное дерево. `gh` на Windows лежит вне PATH у bash — звать `& "$env:ProgramFiles\GitHub CLI\gh.exe"`.

Если публикуется старый релиз задним числом, метка **Latest** уедет на него: GitHub считает последним тот, что опубликован позже по времени, а не тот, у кого версия выше. Чинится `gh release edit vX.Y.Z --latest` на нужной версии — и проверяется, а не предполагается.

Контракт совместимости: ACP protocol integer `1`. Мост поддерживает несколько CLI тем, что **не пинит** `agentVersion`.

## Что лежит в корне

В корне — только то, что читает человек, впервые открывший репозиторий: `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md`, `LICENSE`, `AGENTS.md` / `CLAUDE.md`, `pyproject.toml`. Всё остальное — в каталоги.

Рабочие записки цикла (goal-спеки, evidence, handoff-и) живут в `Service/`: `Service/Handoffs` — результаты текущих циклов, `Service/Audits` и `Service/Research` — отчёты, `Service/Archive` — история завершённых раундов. Восемь файлов вида `GOAL-ROUND*.md` и `START-ROUND8.md` лежали в корне и создавали впечатление брошенной песочницы; они в архиве, ссылки на них в коде и тестах обновлены.

Артефакты прогонов в репозиторий не коммитятся. Исключение — `evidence/live-acp`: эти фикстуры читает `tests/test_live_acp_fixtures.py`, они часть набора, а не след запуска.
