# GOAL — два дефекта, оба измерены, оба ломают работу оператора

> Рабочая папка `D:\ZAI\MCP\Grok CLI`. Вход — 0.22.0, 1007 тестов зелёные.
>
> Оба дефекта нашёл оператор в живой работе, оба воспроизведены здесь замером.
> Ни один не чинится поднятием константы.

## Дефект 1 — голодающий git убивает диспатч

Подготовка lane делает несколько git-проб. У каждой бюджет 60 с. Под нагрузкой
проба его превышает, и **весь** диспатч умирает `GIT_TIMEOUT` — для команды,
которая отработала бы за миллисекунды.

**Измерено на этом хосте**, `subprocess.Popen(['git','--version'])`, медиана из 8:

| | |
|---|---|
| простаивающий процесс | **7.1 мс** |
| 16 потоков, исполняющих байткод | **3258.7 мс** |
| 16 потоков, спящих (столько же, GIL не держат) | **6.5 мс** |

Одна машина, один бинарь, одинаковое число потоков. Разница только в том, держат
ли соседи GIL. То есть дорог **запуск процесса**, а не сам git и не ожидание:
ядер 28, они простаивают, а `Popen` ждёт очереди на GIL.

Это опровергает две ходовые версии. Antivirus и песочница ни при чём — они бы
одинаково влияли на спящие потоки. Комментарий над константой уже говорит нужное
словом `starved`, и уже объявляет намерение: «a slow host is a slow lane, not a
failed one». Сегодня это failed one.

**Правка:** проба, упавшая по таймауту, повторяется один раз; в структурной
ошибке появляются `spawn_seconds` и названная причина; `git --version` кэшируется
на время жизни процесса. Checkout не повторяется — у него свой бюджет и он
законно идёт минутами. Константы не трогать.

## Дефект 2 — длинный честный ответ не доезжает

`ACP_OUTPUT_LIMIT — agent output exceeded reader or queue cap`. Оператор развёл
это экспериментом: пять из пяти заданий **с** ограничением длины ответа прошли,
три из трёх **без** ограничения упали. Длительность ни при чём (прошедшее 211 с,
упавшее 160 с), `reasoning_effort` ни при чём (high прошёл за 96 с).

**Измерено здесь.** Медианный кадр `agent_message_chunk` на проводе — **456
байт**, а CLI стримит ответ кусками в несколько байт: живые события этой сессии
показывают `text_bytes: 4, 1, 2, 7`.

| кусок | раздувание | ответ на 25 КБ стоит |
|---|---|---|
| 2 байта | 228x | 5.84 МБ потока |
| 4 байта | 114x | 2.92 МБ |
| 8 байт | 57x | 1.46 МБ |

Лимит по умолчанию — `max(1_000_000, max_turns * 200_000)`. При включённой
экономии это 12 ходов → 2.4 МБ. Обычный длинный обзор упирается.

**Суть дефекта не в размере лимита, а в том, что считается.** Счётчик берёт
байты JSON-RPC кадров — служебную обёртку транспорта, — а не вывод агента. Два
воркера с одинаковым ответом дадут разные числа только потому, что CLI по-разному
нарезал поток. Плюс переполнение **убивает** job вместо того, чтобы его
ограничить, хотя всё, что мост реально хранит, и так ограничено: события режутся,
summary клипается.

**Правка:** считать полезную нагрузку, а не конверт; при переполнении — мягко
завершать сессию и отдавать receipt с пометкой, как это уже сделано для
исчерпания ходов, а не поднимать `ACPError`. Обе точки: stdio и websocket.
`AGENTS.md` уже обещает «ни одного `ACP_OUTPUT_LIMIT`» — обещание должно стать
правдой, а не смягчиться.

## Порядок работы, заданный оператором

1. Grok думает и делает.
2. Grok-скептик проверяет.
3. Grok вносит правки.
4. Grok-скептик проверяет.
5. Grok вносит правки.
6. Claude — финальный скептик.
7. Claude правит, коммитит, пушит.

Отчёт Grok'а на любом шаге доказательством не является. Каждая находка
воспроизводится своим прогоном до того, как ей поверят, — включая находки
скептика о работе исполнителя.

## Что уже стоило времени в этом заходе

Первое ТЗ по дефекту 1 было написано по **неверной** гипотезе: будто цикл
ожидания не переспрашивает процесс перед объявлением таймаута. Собственный зонд
её опроверг — 0 из 6 — потому что `while proc.poll() is None` в начале цикла и
есть та самая перепроверка. Job отозван, ТЗ переписано по измерению.

Отсюда правило захода: **сначала зонд, потом ТЗ.** Гипотеза, не проверенная
прогоном, стоит одного отменённого job'а и пяти минут воркера.

Второе: `expected_artifacts` первого job'а перечисляли один файл, тогда как само
ТЗ требовало править два. Работа вышла годной и была отклонена гейтом за
`UNEXPECTED_CHANGED_FILES`. Гейт прав, ТЗ нет.
