## Шесть вопросов — коротко

1. Запись вне worktree через permission-гейт: **нет** на junction/UNC/`..`/неизвестном ключе. Symlink-файл на этой машине не создался (нет привилегии); junction как Windows-reparse `Path.resolve()`/`os.path.realpath()` отвергают. ADS и fullwidth-dots остаются внутри worktree.
2. Команда не из `test_commands`: **worker не может** (exact-string). Второй фильтр `_command_allowed` дырявый: пропускает чужой `python.exe` и `Get-Content .env` / `git show HEAD:.env`, если хост такое объявил. См. F-5.
3. Секрет в receipt: **да**, если это не `xai-`/`sk-`/`password=`/`Bearer`/PEM. См. F-1, F-2.
4. Коммит не в `grok/*`: **в production — нет** (`_lane_name` → `normalize_lane` + HEAD от git). `commit_lane_work` сам по себе слабее; git не создаст `grok/../main`.
5. `GROK_DELEGATE_TRUST_HOST_ROOTS=1` + ложный `CLAUDE_PROJECT_DIR`: **да**, этот каталог становится корнем allowlist, в него пишется `.grok-mcp.json`, job можно стартовать. Потомки/соседи — нет. См. F-4.
6. HTTP: loopback без токена = полный `tools/call`. Non-loopback без токена не биндится. См. F-3.

### F-1 redact_text не закрывает типичные токены и пароли в URL
- Серьёзность: major
- Статус: подтверждено репро
- Где: `grok_delegate/contracts.py:374-407` (`_BARE_CREDENTIAL_PATTERN` только `(?:xai|sk)-`; `_SECRET_TEXT_PATTERNS` ждут `key=value`, не URL-userinfo)
- Что не так: один redactor стоит на summary, events, `unified_diff`, `stderr_preview`, durable job, verifier output — и не знает GitHub/AWS/Slack/DSN.
- Как ломается: вход `ghp_<PLANTED-FAKE>` / `github_pat_…` / `AKIA<PLANTED-FAKE>` / `xoxb-<PLANTED-FAKE>` / `postgres://user:s3cret@localhost/db` → `redact_text` возвращает строку без изменений. Тот же вызов через `redact_value` оставляет их в `summary` и `unified_diff`.
- Репро: `%TEMP%\grokmcp-sec\poc_security.py` секция Q3; `py -3 -c "from grok_delegate.contracts import redact_text; print(redact_text('ghp_<PLANTED-FAKE>'))"`
- Последствие для оператора: worker читает `docker-compose.yml` / `settings.py` (это не `.env`, permission пускает) и цитирует DSN в summary — пароль уезжает в receipt, poll, jobs_store. Тесты закрывают только `xai-`/`sk-`/PEM (`tests/test_round8_bridge.py` `test_bare_credentials_and_pem_…`).

### F-2 маркер `sk-`/`xai-`, разрезанный переводом строки, не редактируется даже после склейки
- Серьёзность: major
- Статус: подтверждено репро
- Где: `contracts.py:380-383` (класс `[A-Za-z0-9._-]`, без `\s`); `acp.py:315` (stdio: redact каждой stderr-строки отдельно); для контраста WS `acp.py:527-529` + `619` (join, потом redact)
- Что не так: evidence закрыл split `server-key=` по границе 4096 на WS. `sk-` + перевод строки — другой шов, и он жив даже на joined-строке.
- Как ломается: `redact_text("sk-\nABCDEFGHIJKLMNOPQRSTUV")` → обе половины на месте. `redact_text("sk-")` + `redact_text("PLANTED_SPLIT_TOKEN_1234567890")` → токен цел; `redact_text("sk-"+"PLANTED_SPLIT_TOKEN_1234567890")` → `<REDACTED>`. Stdio кладёт в `stderr_preview` уже построчно отредактированное (`acp.py:315`), поэтому склейка на выходе не спасает.
- Репро: `%TEMP%\grokmcp-sec\poc_security2.py` секция Q3 extra; `%TEMP%\grokmcp-sec\poc_security.py` `stdio-per-line`.
- Последствие для оператора: длинный ключ, который агент или grok stderr перенёс на следующую строку, попадает в `stderr_preview` / summary. WS-фикстура это не ловит.

### F-3 HTTP loopback без токена отдаёт весь MCP, в том числе simple-request CSRF
- Серьёзность: major
- Статус: подтверждено репро
- Где: `http_server.py:79-89` (`token is None` → любой запрос authorized), `:108-118` (`/healthz` без auth), `:121-154` (POST `/mcp` → `handle_jsonrpc` → `tools/call`), `:169-170` (токен обязателен только если host ∉ `{127.0.0.1,::1,localhost}`). CORS/Origin/CSRF нет, `Content-Type` не проверяется.
- Что не так: задокументированный «loopback может без токена» открывает не healthcheck, а job tools. Браузерный simple POST (`text/plain`) не требует preflight.
- Как ломается: `create_http_server(host="127.0.0.1", port=0, token=None)` → GET `/healthz` 200 `{ok, service: grok-delegate}` без заголовков; POST `/mcp` с `Content-Type: text/plain` и телом `tools/call grok_agent_economy` → `structuredContent.ok=true`. Тот же POST с `application/json` тоже 200. `create_http_server(host="0.0.0.0", token=None)` → `ValueError: non-loopback HTTP bind requires GROK_DELEGATE_HTTP_TOKEN` (это держится).
- Репро: `%TEMP%\grokmcp-sec\poc_security2.py` секция Q6. Stdio по умолчанию не затронут; ударяет `--transport http` / `GROK_DELEGATE_HTTP_HOST`.
- Последствие для оператора: любой локальный процесс и страница в браузере могут дернуть `grok_agent_execute` / `grok_agent_project` / `grok_agent_update` на том же loopback, если в окружении сервера уже задан allowlist (типичный рабочий конфиг). Receipts уезжают в HTTP-ответ.

### F-4 `GROK_DELEGATE_TRUST_HOST_ROOTS=1`: ложный `CLAUDE_PROJECT_DIR` становится корнем и принимает `.grok-mcp.json`
- Серьёзность: major (только при включённом флаге; по умолчанию выключен)
- Статус: подтверждено репро
- Где: `guard.py:887-908`; `server.py:525-535` (`host_provided_roots` дописывается в allowlist); `server.py:881-926` (`_handle_project_tool` пишет `config_path(root)` после `path_in_allowlist`)
- Что не так: флаг не «подсказка хоста», а полный корень. Opt-in проекта (`.grok-mcp.json`) после этого ставится тем же MCP-инструментом в названный каталог.
- Как ломается: env `TRUST_HOST_ROOTS=1` + `CLAUDE_PROJECT_DIR=<victim>` без `ALLOWED_ROOTS` → `load_allowed_roots` = `[victim]`. `_handle_project_tool({project_root: victim, preset: "cheap"})` → `ok=true, written=true`, на диске `victim/.grok-mcp.json` с `"preset": "cheap"`. Соседний каталог и родитель → `PROJECT_ROOT_NOT_ALLOWED`, файл не создаётся. Без флага `CLAUDE_PROJECT_DIR` ничего не даёт (`test_host_roots.py`).
- Репро: `%TEMP%\grokmcp-sec\poc_security2.py` секция Q5; плюс уже существующие `tests/test_host_roots.py`.
- Последствие для оператора: враждебный или ошибочный host process выставляет `CLAUDE_PROJECT_DIR` на чужой git-корень → хост-агент пишет opt-in и запускает execute в том дереве (worktree всё ещё `grok/*` рядом, но код и секреты проекта читаются). Потомки корня не открываются — это не `C:\` целиком, пока хост не назвал именно `C:\`.

### F-5 `_command_allowed` не держит второй контур, ради которого он написан
- Серьёзность: major
- Статус: подтверждено репро (гейт); worker по-прежнему не может подменить строку `test_commands`
- Где: `acp.py:1131-1136` (exact match **и** `_command_allowed`); `acp.py:1187-1244` (`tokens[1:]` пропускает argv[0]; `.env` / `HEAD:.env` не `looks_like_path`); `agent_runtime.py:642-657` (verifier зовёт `validated_test_argv` → тот же гейт → `Popen(argv)` без shell)
- Что не так: комментарий и тесты обещают, что даже объявленная команда не пройдёт, если она не в allowlist (`pytest -q; echo` режется). Allowlist принимает интерпретатор вне worktree и чтение `.env` через git/Get-Content.
- Как ломается:
  1. `C:\Users\…\Temp\<outside>\python.exe -m pytest -q` → `_command_allowed=True`, `_command_paths_confined=True` (первый токен не проверяется). Если эта строка в `test_commands`, permission = `allow-once`, verifier сделает `Popen` этого exe.
  2. `Get-Content .env` и `git show HEAD:.env` → оба `allowed=True`. Permission при `test_commands=[эта строка]` = `allow-once`. Для git verifier реально выполнит `git show` и положит содержимое в `output_preview` (потом `redact_text`, см. F-1).
  3. `python -m pytest --rootdir=<outside>` — **режется** (после `=` путь проверяется). Вложенное `--override-ini=addopts=--rootdir=<outside>` гейт **пускает**; живой pytest 8 на этой машине rootdir так не сменил (1 passed из cwd). Эту строку как FS-escape не воспроизвёл.
- Репро: `%TEMP%\grokmcp-sec\poc_security2.py` секция extra Q2; `validated_test_argv` для (1) возвращает argv с абсолютным python вне cwd.
- Последствие для оператора: exact-match защищает от worker'а, который шлёт *другую* строку. Он не защищает, если оркестратор (сам хост-агент) положил в пакет предложенную worker'ом или ошибочную команду. Второй фильтр для этого и существует — и здесь он не срабатывает.

## Проверено и оказалось в порядке

- **`..`, UNC `\\?\`, UNC share, абсолютный путь снаружи** — `_paths_confined` / `permission_decision` → `reject-once`. `Path.resolve()` и `os.path.realpath()` на этой машине совпали.
- **Junction (`mklink /J`)** — создаётся без Developer Mode; запись `junc-out/secret.txt` resolve'ится в outside и **отклоняется**. Directory symlink в evidence по-прежнему skip; поведение reparse через junction проверено.
- **File/dir symlink** — `WinError 1314`, не воспроизвёл. Код тот же `Path.resolve()`, что на junction.
- **Неизвестный path-ключ один** (`filename=outside`) — fail-closed (`_PATH_KEYS` без эвристики). `target_file` уже добавлен по evidence, не дыра.
- **`path` внутри + `destination` снаружи** — оба ключа в `_PATH_KEYS`, отказ.
- **`.env` / `auth.json` / `*.pem` через read/write tool** — отказ. `.ssh/id_rsa` **не** в ACP-списке (в `guard.py` `_SENSITIVE_READ_PATTERNS` он есть) — это ужесточение denylist, не выход из worktree; PEM в receipt всё равно режется.
- **NTFS ADS `inside.txt:hidden`** — гейт пускает, `dir /R` показывает `inside.txt:hidden:$DATA`, но это поток файла *внутри* worktree, не escape. Git ADS не трекает (вне среза receipt-truth).
- **NFC/NFD / fullwidth `．．`** — остаются именами внутри cwd; Windows не сводит их к `..`.
- **Exact `test_commands`** — `; && | & $() backticks newline` режутся; команда не из списка — `reject-once`, даже если regex её любит (`npm test`, `git log`, `py -3 -m pytest -q`).
- **`python -m pytest --rootdir=outside` и `-c outside\conftest.py`** — path-конфайнмент срабатывает (в том числе форма `--flag=path`).
- **`allow_always` из live permission-cancel** — `permission_decision` выбирает только `allow_once` / `reject_once`, session-wide edits не выдаёт.
- **`normalize_lane`**: `grok/../main`, `grok/`, newline, `refs/heads/grok/x`, `grok/main`, unicode lookalike, `grοk/x` — отказ. `Grok/x` нормализуется в `grok/x`.
- **`commit_lane_work` + production path**: `main` / `Grok/x` / `refs/heads/grok/x` не коммитят. Вызов идёт с `_lane_name` (`agent_runtime.py:884-889`), который сначала выкидывает всё кроме `[a-z0-9-]`, потом `normalize_lane`. Искусственный git с HEAD=`grok/../main` «закоммитил» бы — такого ref git не создаёт.
- **`_reject_forbidden_git_args`**: push/merge/pull/rebase/reset/clean режутся; `checkout` разрешён (нужен worktree), worker через этот runner git не собирает. Push из `commit_lane_work` невозможен.
- **WS `GROK_AGENT_SECRET` / `server-key=`** — редактируется; evidence + `test_websocket_secret_is_redacted_in_both_daemon_formats`. Не дублирую.
- **Чанки `agent_message_chunk`** — в events текста нет (`text_redacted: true`), join+redact на summary. Для `sk-` без перевода строки это работает.
- **HTTP non-loopback без токена** — bind отвергается.
- **TRUST_HOST выключен** — `CLAUDE_PROJECT_DIR` не расширяет allowlist. Сосед и родитель host-root не входят даже при флаге.
- **Extra keys `env` / `working_directory` / `is_background`**: permission смотрит только `command`. Live 1.0.4 шлёт `is_background` (тот же pytest). Поля `env`/`workdir` в capture нет — что CLI с ними сделает, **предположение**, не находка.
